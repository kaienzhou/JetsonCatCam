# JetsonCatCam

固定机位的本地 AI 猫咪相机，跑在 Jetson Nano 2GB 上。不上云，手机浏览器直接看。

- 手机或电脑浏览器里看实时画面，用手指直接在画面上**画区域**（沙发、食盆、猫爬架……），保存后马上生效
- 猫进入或离开区域时记录事件，进入时还会留一张照片，可推送到手机
- **历史记录**：每天各区域停留多久、一天里什么时候在哪、每次出现的照片，可导出 CSV
- 要**访问口令**才能看；网页可以添加到手机主屏幕，当 App 用
- 检测用 COCO 预训练模型（含 `cat` 类），**不需要自己训练**：默认的 jetson-inference `ssd-mobilenet-v2`，或精度更好的 YOLOv8n（TensorRT）

## 在 Jetson 上运行

前提：JetPack 4.6（L4T R32.6/32.7，Python 3.6），已装好 [jetson-inference](https://github.com/dusty-nv/jetson-inference) 的 `L4T-R32.7.1` 分支（带 Python 绑定），摄像头接好。

```bash
git clone <本仓库> && cd JetsonCatCam
cp config.example.json config.json    # 按你的房间改 camera 和 zones
python3 -m catcam --backend jetson
```

首次启动会为 `ssd-mobilenet-v2` 构建 TensorRT 引擎，**要等几分钟**（板子上实测约 280 秒）。

**第一次启动时会生成访问口令**，并打印在日志里（用 systemd 的话看 `journalctl -u catcam`）。随时在项目目录里查看：

```bash
python3 -m catcam code        # 显示口令和一个自动登录的链接
python3 -m catcam new-code    # 换新口令，所有已登录的手机和电脑都要重新登录
```

然后手机或电脑浏览器打开 `http://<jetson-ip>:8080`，输入口令（或直接打开 `code` 命令给出的链接）。登录一次后浏览器会记住 180 天。

没有硬件时可以用模拟猫（一间小房间里走来走去的猫）测界面和逻辑，需要 OpenCV 才有画面：

```bash
python3 -m catcam --backend fake      # 配置里加 "fake": {"speed": 0.3} 让猫走快一点
python3 -m unittest discover -s tests
```

## 网页 App

- **实时**：视频、猫现在在哪个区域、今天各区域停留时间、最近事件（带照片）。没人看的时候板子不画图也不压 JPEG，更省电。
- **历史**：最近 7 / 14 / 30 天每天的停留时间（按区域叠起来的柱状图）；点某一天看它按小时的分布和当天所有事件；可导出 CSV。
- **区域**：在一张没有叠加图形的实时画面上画区域。点「＋ 新区域」依次点出几个角；点区域选中它，拖圆点改形状，拖区域里面整体移动，点边线加顶点，长按圆点删顶点。保存后立刻生效，不用重启。
- **设置**：设备信息、存储用量、导出全部记录、退出登录；还有「检测诊断」：打开后直播画面上会画出模型看到了什么（黄框是认出的猫，灰框带问号是"有点像猫但没到阈值"，白色细框是检测范围），猫离得远却没被认出来时先看这个；「存一张样本」把当时的原始画面和模型的判断存下来，用来分析为什么没认出来，以后也能用来训练只认你家猫的模型。

手机上把它加到主屏幕：iPhone 用 Safari（分享 → 添加到主屏幕）；安卓用 Chrome（菜单 → 添加到主屏幕）。通过普通 HTTP 访问时，安卓只能做成"快捷方式"，要完整的"安装"需要 HTTPS。

### 数据放在哪

都在 `data/`（可用 `data_dir` 改）：

| 文件 | 内容 |
|---|---|
| `catcam.db` | 所有事件（SQLite，写入是原子的，断电不会留下写了一半的记录；文件损坏时会改名保留并重新开始） |
| `snapshots/` | 出现和进入区域时的照片，默认保留 30 天、总共不超过 500 MB |
| `samples/` | 在「设置」里手动存的样本：原始画面（`.jpg`，没有任何标注，是检测器看到的大小）和模型当时的判断（`.json`），最多保留最新 300 张。只存在这台相机上 |
| `access_code`、`secret` | 访问口令和签名密钥（只有自己能读） |

旧版的 `events.jsonl` 会在第一次启动时自动导入一次。

### 接口

登录后（cookie，或请求头 `Authorization: Bearer <口令>`）可以用，方便写脚本：

| 路径 | 内容 |
|---|---|
| `GET /api/hello` | 不用登录：`{"app": "catcam", "api": 1, "version", "name", "login"}`，客户端用它认出相机 |
| `GET /api/state` | 现在的状态、今天各区域停留、最近事件 |
| `GET /api/history?days=14` | 每天各区域的停留秒数和次数 |
| `GET /api/day?date=2026-11-16` | 一天里按小时的分布和事件 |
| `GET /snap/<事件 id>.jpg` | 事件照片 |
| `GET /api/export.csv?days=365` | 导出事件 |
| `GET/POST /api/zones` | 读取 / 保存区域 |
| `POST /api/debug` | `{"on": true}`：打开 / 关闭直播画面上的检测诊断 |
| `POST /api/sample` | 保存当前的原始画面和模型的判断，返回样本名字 |
| `GET /api/samples`、`GET /sample/<名字>.jpg`（或 `.json`） | 样本列表；取回样本 |
| `GET /stream.mjpg` | 实时视频（最多同时 6 路） |

### 安全

口令连错 5 次会把那个地址锁 1 分钟。页面和视频没有加密（普通 HTTP），所以**只在信得过的局域网里用**；要从外面看，请走 VPN（例如 Tailscale），不要把端口直接映射到公网。

## 配置要点

`config.json` 里的坐标全部是 0 到 1 的归一化坐标，左上角为原点。

- `zones`：多边形顶点列表，按顺序排列。平时在网页的「区域」页里画就行，保存时程序会改写这一项（其余内容不动，并留一份 `config.json.bak`）。
- `data_dir`：数据目录，默认 `data`，放历史库、事件照片和口令文件，见"数据放在哪"。
- `auth`：`{"enabled": true, "code": ""}`。`code` 留空就用自动生成的随机口令，想用自己的口令就填在这里；`enabled` 设成 `false` 会关掉口令，只在完全信得过的网络里这么做。
- `snapshots`：`{"enabled": true, "keep_days": 30, "max_mb": 500}`，事件照片的开关、保留天数和总大小上限。
- `samples`：`{"enabled": true, "keep": 300}`，手动保存的样本的开关和最多保留几张。
- `fake`：只对 `--backend fake` 有效，例如 `{"speed": 0.3}`。
- `log`：旧版事件日志的路径，只在第一次启动时导入一次。
- `tracker.enter_frames`：连续多少帧在区域内才算进入（防误检抖动）。
- `tracker.leave_seconds`：离开区域多久才算离开（猫短暂探头不算）。
- `notify.url`：推送地址模板，`{title}` 和 `{body}` 会被替换，例如 Bark：`https://api.day.app/<key>/{title}/{body}`。`notify.zones` 指定哪些区域进入时推送。
- `debug`：设为 `true` 时直播画面里画出模型看到了什么：黄框是认出的猫（带置信度），灰框带问号是"有点像猫、但没到 `min_conf`"，白色细框是检测范围。网页「设置」页里的「检测诊断」开关可以随时打开和关闭，不用改配置。YOLO 要同时设 `detector.all_classes: true` 才会报告猫以外的物体。
- `max_fps`：处理帧率上限，0 为不限制。限制后 GPU 有空闲，发热和功耗都更低；盯猫 4～15 帧/秒足够，引擎越大，这个数要设得越小，见"识别距离"。
- `detector`、`camera`：见下文。

## 检测模型

`config.json` 里的 `detector` 选择检测器：

```json
"detector": {"type": "ssd", "min_conf": 0.4}
"detector": {"type": "yolo", "engine": "models/yolov8n_768x1024.fp16.engine", "min_conf": 0.3, "max_fps": 4}
```

YOLO 的可选项：

- `min_conf`（默认 0.4）：置信度达到多少才算认出猫。远处的猫置信度本来就低，0.3 左右比较合适；太低会把靠垫、毛绒玩具当成猫。
- `max_fps`（默认 0，每帧都检测）：检测器每秒最多跑几次。引擎大的时候设 4 左右：检测慢一点，但视频仍然按摄像头的帧率走，GPU 也有空闲（更省电、更不容易触发过流）。
- `zoom`（默认 `true`）、`zoom_margin`（0.08）、`zoom_min`（0.3）：只看区域所在的那块画面并放大，见"识别距离"。
- `iou`（0.5）：同一只猫的重叠框合并的阈值。
- `all_classes`（默认 `false`）：设成 `true` 时诊断画面里也会显示猫以外的物体。
- `weak_conf`（默认 0.1）：低于 `min_conf`、高于它的"疑似猫"，诊断画面里用灰框带问号显示，不参与判断。

### 为什么要换 YOLO

用 `tools/size_test.py` 把猫图缩小贴进真实房间画面测试：`ssd-mobilenet-v2` 要求猫宽度占画面的 25%～45% 以上才可靠（约 1～1.3 米内），再小就基本检不到。偏色（NoIR 白天偏紫）对它影响不大，瓶颈是目标大小。

### 准备 YOLO 引擎

1. 在普通电脑（Linux / WSL）上导出 ONNX：`bash tools/export_yolo.sh`（用独立 venv，装 CPU 版 PyTorch 和 ultralytics，权重来自官方发布，约 6 MB）。默认导出 384×512、480×640、576×768、768×1024 四种输入尺寸（高×宽），只要其中几种用 `SIZES="768x1024" bash tools/export_yolo.sh`。
2. 把 `.onnx` 复制到 Jetson 的 `models/`，在 Jetson 上编译引擎（引擎只能用于编译它的那块 GPU 和 TensorRT 版本）：

   ```bash
   sudo systemctl stop catcam              # 先停掉服务，让编译独占内存和 GPU
   bash tools/build_engine.sh 768x1024     # 384x512 约 10 分钟，576x768 约 13 分钟，768x1024 要 20 分钟以上
   sudo systemctl start catcam
   ```
3. 冒烟测试：`python3 tools/smoke_detect.py --engine models/yolov8n_384x512.fp16.engine <图片>`；测速：`python3 tools/bench_yolo.py <引擎> --frame 640x480`。

输入尺寸都是 3:4，和摄像头 4:3 的画面一致，不需要补边。输入越大，越远、越小的猫越认得出来，但耗时按像素数增长，见下面的"识别距离"。

## 识别距离

**猫在检测器输入里有多宽（像素），决定认不认得出来。** YOLOv8n 要猫有 70 像素宽左右才稳（置信度 0.3 以上），小于 40 像素基本认不出。Pi 摄像头 V2 视野 62°，35 厘米宽的猫（侧着走或趴着）在检测器输入里的宽度：

| 检测器输入的宽度（整个 62° 视野） | 2 米 | 3 米 | 4 米 | 5 米 | 6 米 |
|---|---|---|---|---|---|
| 512（旧默认：640×480 的画面，网络输入 512×384） | 74 | 50 | 37 | 30 | 25 |
| 768（576×768 引擎） | 111 | 74 | 56 | 45 | 37 |
| 1024（768×1024 引擎） | 149 | 99 | 74 | 59 | 50 |
| 1640（传感器的原始分辨率，只看一块区域时） | 238 | 159 | 119 | 95 | 79 |

坐着正对镜头的猫只有 22 厘米宽，上面的数字要乘 0.63。旧默认在 3 米处猫只有 50 像素（坐着的 31 像素），正好落在"认不认得出"的边缘，这就是"3 米左右认不出来"的原因。

### 三个办法，可以叠加

1. **更大的引擎**（`detector.engine`）：768×1024 的引擎让猫在输入里大一倍，代价是网络耗时约 4 倍（见下表）。
2. **只看区域并放大**（`detector.zoom`，默认开）：区域圈得集中时，检测器只看区域所在的那块画面，并且直接取传感器的原始像素，等于数码变焦，花的时间却不变。画面要用传感器的原始大小（`camera.width/height` 写 1640×1232），否则没有更多像素可看。网页「区域」页里的白色虚线框就是检测范围，框外的猫不会被认出来。区域满屏或分散在画面各处时，框盖不住大部分画面，这一项自动不起作用。
3. **让猫在画面里更大**：摄像头离猫常待的地方近一点、高一点往下看；或换窄视角（长焦）的镜头。这是最有效的办法，什么算力都不用花。

另外，**缩放算法**也有影响：传感器画面缩小时，GStreamer 的 `nvvidconv` 默认用最近邻，会直接丢像素，现在默认改成了高质量算法（`camera.interpolation`）。

### 实测

`tools/range_test.py` 把 4 张猫图（切出猫，按真实大小）贴进 2 个房间画面，再走和摄像头画面一样的路径（传感器画面 → 缩放 → 网络），加了镜头模糊和噪声。表里是跟踪器能认出来（置信度 ≥ 0.3）的比例。

| 设置 | 一帧耗时 | 2 米 | 3 米 | 4 米 | 5 米 | 6 米 |
|---|---|---|---|---|---|---|
| 旧默认：640×480 画面（最近邻缩放）+ 384×512 引擎 | 40 ms | 50% | 29% | 0% | 0% | 4% |
| 同上，缩放换成高质量算法 | 40 ms | 46% | 38% | 8% | 0% | 4% |
| 768×576 画面 + 576×768 引擎 | 72 ms | 67% | 50% | 38% | 21% | 0% |
| 1024×768 画面 + 768×1024 引擎 | 122 ms | 75% | 50% | 54% | 46% | 13% |
| 只看一块区域（窗口宽约画面的 31%，原始分辨率）+ 384×512 引擎 | 约 40 ms | 100% | 79% | 54% | 58% | 42% |
| 只看一块区域（窗口宽约画面的 45%）+ 384×512 引擎 | 约 40 ms | 96% | 67% | 58% | 58% | 46% |

（35 厘米宽的猫；每格 24 次试验的平均，所以有几个百分点的抖动。耗时是板子上实测的整帧时间，包括缩放和后处理。）这是用猫的照片贴出来的，比真猫乐观（照片比真猫透过小镜头看到的更清楚），看各行之间的差别比看绝对数字更有意义。第一行就是旧默认：3 米处只有约 30% 的试验认得出，4 米以外几乎认不出，和实际使用时的反馈一致。

再比一组：大引擎放进"只看一块区域"的窗口里（窗口宽约画面的 45%，等于把窗口里的像素放大 1.4 倍给网络看），同一批猫图：

| 设置 | 2 米 | 3 米 | 4 米 | 5 米 | 6 米 | 7 米 |
|---|---|---|---|---|---|---|
| 整幅，1024×768 画面 + 768×1024 引擎 | 100% | 75% | 50% | 33% | 33% | 8% |
| 只看区域，原始分辨率 + 384×512 引擎 | 100% | 100% | 100% | 50% | 42% | 33% |
| 只看区域，放大 1.4 倍 + 768×1024 引擎 | 100% | 92% | 100% | 100% | 50% | 50% |

（这一组的猫图是用 768×1024 引擎切出来的，和上一张表的猫图不完全一样，所以不能直接拿数字对比，只看同一张表里各行的差别。每格只有 12 次试验，抖动在 15 个百分点左右。）区域窗口 + 大引擎最远，但每帧要 120 毫秒左右。

想在自己的板子、自己的房间画面上测，拍一张没有猫的房间照片当背景（摄像头 1640×1232 的原图最好），再跑：

```bash
python3 tools/range_test.py --degrade 房间.jpg ~/jetson-inference/data/images/cat_*.jpg \
    --pipe 640x480:models/yolov8n_384x512.fp16.engine \
    --pipe 1024x768:models/yolov8n_768x1024.fp16.engine \
    --pipe win@1.4:models/yolov8n_768x1024.fp16.engine
```

在板子上整套跑起来的资源占用（没有人看网页时，各测 60 秒）：

| 配置 | 一次检测 | CPU（一个核的百分比） | 过流告警 | 可用内存 | GPU 温度 |
|---|---|---|---|---|---|
| 旧：640×480 画面，384×512 引擎，每帧检测（约 15 次/秒） | 40 ms | 约 63% | 0 | 约 310 MB | 43 ℃ |
| 新：1640×1232 采集，768×1024 引擎，`detector.max_fps: 4` | 130～160 ms | 约 70% | 0 | 约 210 MB | 44 ℃ |

新配置下网页上的视频仍有 10 帧/秒左右。有区域窗口时一次检测比没有窗口时快 20～30 ms（裁一块再放大，比把整幅缩小便宜）。

### 怎么选

- **区域圈得集中**（沙发、食盆在画面的一角或一侧）：保持 `zoom` 开着，画面用 1640×1232，引擎用 384×512（流畅，15 帧/秒）或 768×1024（更稳）。
- **区域满屏或分散**：用 768×1024 引擎，`detector.max_fps` 设成 4 左右。
- **供电**：GPU 重载时内核会打 `soctherm: OC ALARM`（过流告警，板子在给自己限流），重载太久还可能掉电复位。用 `bash tools/power_watch.sh` 看设置压板子压到什么程度；大引擎请把 `detector.max_fps` 设低，让 GPU 有空闲。
- 阈值 `min_conf`：打开网页「设置」里的「检测诊断」，灰框是"有点像猫但没到阈值"的，能看出该把阈值降到多少。降低阈值会让远处的猫更容易认出来，也会让靠垫、毛绒玩具更容易被当成猫。

## 使用 CSI 摄像头（Raspberry Pi Camera V2 / NoIR V2）

两者都是 IMX219，JetPack 4.6 自带驱动。`camera` 里写：

```json
"camera": {"source": "csi://0", "width": 640, "height": 480, "rate": 30, "rotate": 0,
           "sensor_mode": 3, "sensor_width": 1640, "sensor_height": 1232,
           "interpolation": 5, "display_width": 640}
```

- `width`/`height` 是送去检测的画面大小；传感器模式 3 是 1640×1232、30 帧/秒（全视野，2×2 合并像素，暗处更干净）。网页上的画面会缩到 `display_width` 宽（默认 640），所以检测用大画面不会拖慢手机上的视频。
- `interpolation`：传感器画面缩小时用的算法，对应 GStreamer `nvvidconv` 的 `interpolation-method`：0 最近邻、1 双线性、2 5 抽头、3 10 抽头、4 智能、5 最佳（默认 5）。**`nvvidconv` 自己的默认值是 0（最近邻），缩小时直接丢像素，远处小目标的细节会被毁掉**，所以这里默认用 5；这一项零成本（VIC 硬件做的）。
- `rotate`：画面方向，0 / 90 / 180 / 270（顺时针度数）。0 是传感器原方向。
- 2GB 版只有一个 CSI 口。排线的银色触点一面朝向散热片，蓝色加强片朝外（这是 Jetson Nano 4GB 资料里的插法，2GB 接口规格相同但没找到官方确认；务必断电后再插拔）。
- **CSI 采集不是用 jetson-utils 自带的 `csi://`，而是 OpenCV + GStreamer。** 原因：jetson-utils 在这套环境下，只要不转 180° 就会报 `nvbuf_utils: dmabuf_fd ... mapped entry NOT found` 然后进程直接退出，还会把摄像头服务（nvargus-daemon）带崩。
- NoIR 没有红外滤光片：白天画面偏紫红。实测对检测影响很小（置信度基本不变，自动白平衡也无益）。夜里配 850nm 红外补光灯可以看到猫，但画面是灰度，效果需要实测。
- 补光灯放在镜头旁边斜着打，别正对镜头，否则反光。
- V2 水平视角约 62°。

USB 摄像头：`"source": "/dev/video0"`，走 jetson-utils，`width`/`height` 是采集大小。

## 开机自启

```bash
sudo bash deploy/install-service.sh        # 装成 systemd 服务，开机自启，退出后自动重启
systemctl status catcam                     # 状态
journalctl -u catcam -f                     # 看日志
sudo bash deploy/install-service.sh --remove
```

程序在摄像头 20 秒没有新画面时会主动退出，服务会先重启摄像头服务（nvargus-daemon）再把它拉起来。在网页上改区域不用重启；手改了 `config.json` 的其他项后，`sudo systemctl restart catcam` 生效。

给板子起个好记的名字，局域网里就能用 `http://catcam.local:8080` 访问（电脑或手机开着代理时，`.local` 名字有时会被代理劫持，打不开就还是用 IP）：

```bash
sudo bash deploy/set-hostname.sh              # 改成 catcam
sudo bash deploy/set-hostname.sh living-room  # 或者别的名字（小写英文字母、数字和 -）
```

### 关掉桌面（推荐）

2GB 板子的内存很紧，不接显示器用的话把图形界面关掉：

```bash
sudo systemctl set-default multi-user.target   # 以后开机不起桌面
sudo systemctl isolate multi-user.target       # 立刻关掉当前桌面
# 想恢复：sudo systemctl set-default graphical.target && sudo reboot
```

实测关桌面后可用内存约增加 70 MB。内存仍然紧张时，还可以停掉用不到的服务（例如 docker）。

## 供电

Jetson Nano 2GB 只有一个 USB-C 供电口，要求 **5V/3A**。供电不够时，板子在 GPU 满载时会直接**掉电复位**（内核启动日志里是 `TEGRA_POWER_ON_RESET`，而且没有正常关机记录；手动拔插电源也会留下同样的记录，先排除人为断电），摄像头也可能随之报错。

- 用标称 15W 以上的 USB-C 充电头，不要用电脑 USB 口。
- 线要短而粗（1 米以内、能跑 3A）。有 USB 功率计的话看满载时的电压，低于 4.75V 就有问题。
- 板子上别再接耗电的 USB 设备。
- 供电条件一般时：用 384×512 的引擎并设置 `max_fps`（10～15）；用大引擎时把 `detector.max_fps` 设低（768×1024 设 4 左右），让 GPU 有一半以上的时间空闲。
- 想知道自己的设置把板子压到什么程度：`bash tools/power_watch.sh 120` 数内核的过流告警。上面两种配置各测 60 秒都是 0 次；换新配置前后各测一次最放心。

## 已知限制

- 默认只追踪画面里置信度最高的一只猫。
- 板子没有电池时钟：断电重启后时间要靠联网校时。刚开机的几十秒里，或者网络没通时，时间可能不对，这期间记下的事件时间也会不对。
- 只有一个共用的访问口令，不分用户；页面和视频不加密（普通 HTTP）。
- 区域判定用检测框中心点，俯拍效果最好；平视时猫在远处会和近处的区域重叠。
- JetPack 4.6 是 Nano 的最后一个系统版本（Python 3.6），不会再更新。
- 2GB 板子内存很紧：应用约占 1 GB，带桌面系统时只剩约 100 MB 余量，产品化时建议关掉桌面（`sudo systemctl set-default multi-user.target`）。

## 路线图

1. 无线网络：USB 网卡、存多个 Wi-Fi、手机热点兜底，没有屏幕也能配网（现在要接网线）
2. 从外面看：走 VPN（如 Tailscale）；上 HTTPS 以后网页才能完整"安装"、才能收网页推送
3. 推送带上事件照片
4. 只读根文件系统，防 SD 卡损坏（数据放单独的可写分区）
5. 一键刷写的 SD 卡镜像
6. 3D 打印外壳（散热、摄像头支架、壁挂）
